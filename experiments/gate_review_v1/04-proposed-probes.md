Status: defined; JSON schema specified, execution adapter not yet implemented. Use one fresh PROPOSE_PROBE call for a selected pair, not a rewrite-to-fit call. Inputs: original source, two frozen hypotheses, prior public observations and catalog. Output: bounded literal-string construction, predictions under H1/H2, explanation of why expected outcomes differ, no patch or Python/shell code. Must commit opposite decisive predictions (fast vs slow) BEFORE observing proposed-input runtime. Those are model-claimed implications, not validated facts about the hypotheses.

Safe executable interface is a host-owned DSL, not model-generated scripts: input = concatenate at most8 segments; each segment literal<=256 chars, repeat integer1..6000; total UTF-8 length<=131072 bytes; optional base_url<=2048 chars. No eval/exec, imports, paths, shell commands, writes or arbitrary callable selection from proposal. Malicious-looking strings remain target input data, never instructions. Reject oversized/malformed inputs and signatures already used as a public probe; save rejection, do not silently repair or run it. Max1 pairwise proposal at a time, max2 proposals/trajectory, no unbounded repair loop.
