# Repair strategy ablation v1 — sequential A, B, C

Single observed w3lib_264 issue, sanitized issue + exact block, same local12B/31B checkpoints and16K TP2 runtime. Retain prior feedback-edit-v1 as historical512-output baseline. Each new arm stored separately; do not combine into overall autonomous score.

A / feedback-budget-v1: same feedback workflow and public/independent graders as method19, change output ceiling512→1536 per generation, max3 edit generations/model. Other model inputs and settings preserved. API HTTP timeout raised120→240s to accommodate larger allowed output; not an extra model retry. First gen and two feedback repairs, early stop only on public pass. Independent grade final API candidate.

B / diagnosis-edit-v1: same issue, feedback, cumulative source and tool. Initial edit1536 tokens; before each subsequent edit, separate call for a brief three-field decision summary (failed_observation, suspected_cause, next_change), cap384, followed by edit cap1152. No request for hidden chain of thought. Max total generated-token allowance4608/model, same as A. Additional calls and changed partition of output budget are part of this strategy, so not a pure prompt-only causal contrast. Thinking remains off. Model-written diagnosis is a hypothesis, not correctness evidence; archive it and evaluate patch externally.

C / candidates-edit-v1: generate3 independent candidates, each from original source without previous candidates or feedback. Same initial issue/prompt/tool, cap1536 each =4608 tokens/model. temperature0.6 with seeds17,29,43 to permit diversity; A/B temperature0. This sampling change is explicitly part of independent-candidate strategy. Execute and publicly test each candidate independently. Select ONLY using public pass, functional pass, measured public runtime, then attempt index. Public-passed means both performance and functional tests. Missing runtime sorts last. Grade only selected candidate with independent grader; never use hidden outcomes to rank or return to choose again. No guarantee of diverse outputs even with distinct seeds.

Across arms max18 edit generations, up to4 brief decision calls in B (2 repairs×2 models). Max36 raw/API candidate executions +6 independent final grades. Early stopping reduces A/B totals; C always samples3. Equal maximum generated tokens is not equal actual tokens, walltime, input tokens or call count. Report each budget measure. No seed/task replication, historical baseline, no population or statistical claims. Different temperature and model order can affect results; not a clean isolation of every mechanism.

Public diagnostic from method19 at6000, existing67 functional tests. Independent final grader from method18 at2K/4K/8K/30K and URL cases, not model-visible. Validated preflight artifacts reused; grader sources frozen and unchanged. Raw/API same-generation capture and separate execution for each edit. Missing/truncated raw decoding remains explicit. Invalid call keeps cumulative source in A/B; C always resets original.

Finite controller scripts/run_repair_strategies.py executes A→B→C as subprocesses with per-arm source freeze + shared GPU lock in each worker. No recurring rerun trigger. A order12B/31B, B31B/12B, C12B/31B to reuse loaded model between arms. Workers update report after each measured candidate and final grade; controller updates aggregate comparison after each arm and on failure. If infrastructure failure occurs, stop needs_review instead of skipping or overwriting partial output. Source/report contents frozen while arm active; append final analysis after complete.
