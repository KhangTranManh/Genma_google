Cách đọc kết quả

Đo cả patch pass bị skip / skipped được chấm và patch pass bị skip / tổng patch pass. Nếu không có patch pass, tỷ lệ loại nhầm trong nhóm thành công là chưa xác định, không phải0%. Generation failure và infrastructure missing được ghi riêng. Kết quả1 issue không chứng minh gate an toàn trên task khác.

Điều chỉnh kết luận cũ

Chưa quan sát Patch cho8 hồ sơ bị skip; chưa thể nói gate đã loại được các hướng không thể sửa. Các policy cũ chỉ chứng minh được việc thi hành điều kiện, không chứng minh điều kiện có ích. Ngoài ra, rule “không có dự đoán trái nhau” trước đây rộng hơn duplicate vector và có thể gom nhầm các dự đoán khác nhau.

P0 · Audit gate · đặc tả đầy đủ
# 1. Offline audit: measure counterfactual patch outcomes before trusting the gate

Status: defined, not executed. Priority P0; precedes policy optimization. Question: can the SAME assigned hypotheses rejected/deferred by the old gate produce a correct patch under its actual Patch interface?

Population: all saved complete hypothesis records in role-probes-v1 rankings (12B3,31B3) and revise-hyp-v1 revised ranking (31B3). Include original gate-allowed records as controls; do not sample only skips. revise-hyp12B Localize truncated and has no complete hypotheses, so exclude as generation-stage missing data, not three failures. Manifest preserves9 records,8 skipped and1 allowed, with source/ranking/hash provenance. Treat each source trajectory separately; earlier vs revised hypotheses are dependent, not9 independent tasks. Do NOT deduplicate the audit population because grouping is itself under audit.

For EACH record: construct the original branch's Patch prompt from original code, assigned hypothesis and exactly the evidence the old Patch role would have received; keep model/checkpoint/schema/temperature0/thinkingoff/output1536, one call from original snapshot. Preserve raw/API/replay. Never inject the eventual correct expression, new audit results, other candidate patches or later revealed probes. Archive exact request and validate it against the original allowed-call template. Existing allowed capture is a historical reference; generate one new matched control as part of the audit instead of mixing old runtime results with new trials. Gate decisions remain frozen; all9 patches run regardless of their gate decision.

Grade every applicable API candidate independently in a clean offline container, not just whichever policy selects. Existing public performance6000+67 functional tests+semantic guard0/200/1000, and frozen independent2K/4K/8K/30K+valid URL/attribute300/1500. Freeze a new audit grader bundle with positive/negative preflight before calls. Grade by behavior, not exact reference diff. Raw/API mismatch investigated separately; API behavior is primary operational outcome, not evidence of intrinsic reasoning ability. Invalid/truncated call consumes attempt and counts as non-success in a budgeted operational estimate. Infrastructure/invalid grader results are missing, not ordinary model failures. Report call validity and functional/semantic/performance layers separately.

Metrics with counts and denominators:
- missed_success_yield = rejected AND verified_patch_pass / completed scorable rejected attempts. Planned denominator8; do not silently retain8 if infrastructure data missing.
- false_negative_rate_among_successes = rejected AND pass / all verified passes across rejected+allowed. If zero successes, report undefined, not0% or proof the gate is safe.
- allowed_patch_yield, audit coverage, generation failures, infra missingness, model/trajectory stratification.
- attainable_success_without_gate vs with_old_gate at same realized candidate pool; if any verified pass was skipped, gate discarded an observed usable candidate. Do not estimate stable causal effect from one seed or one issue.

A skipped hypothesis producing a verified pass is direct evidence of harmful suppression in that case. All skipped failing in one generation does NOT validate gate or establish correlation between prediction accuracy and patch success. Replay candidate outcomes under old gate, rank-only and original-order policies with fixed patch-call budgets1/2/3 per trajectory. This is candidate-pool/offline replay with no adaptive feedback, not a new online agent score. Final grader labels are evaluator-only; never enter real selection prompts.

Stop/report after audit before enabling destructive pruning. Append results to new report; preserve earlier reports and conclusions as historical, add explicit correction that gate utility was unmeasured. Audit runner and request-template reproduction validation still need implementation; manifest/config/policy definitions alone do not execute it.
P1 · Xếp hạng · đặc tả đầy đủ
# 2. Prediction ranks attempts; tests decide patch acceptance

Status: defined, standalone ranking helper implemented/tested; no model run. Default replaces prediction rejection with ordering only. Hypotheses with prediction errors remain in queue. Missing/uncertain predictions are not false outcomes; structurally invalid hypotheses need a separate logged handling path, never guessed repairs.

Deterministic ordering: more decisive matches, fewer contradictions on declared public diagnostic observations, then weak source-evidence/Ochiai, original stable index. Freeze prediction/evidence versions before ordering; exclude hidden final grader and held-out transfer measurements until their declared reveal phase. Every valid trajectory gets at least one Patch attempt when budget>=1, even if all hypotheses are weak. Original-source patch each time, no writer context reuse. Strictly retain only public reproducer pass +zero functional/semantic regression; no gain from tiny timing noise. No retained candidate means no submission. One independent final grade of the publicly selected candidate; evaluator can inspect other candidates only in the separate audit, without affecting selection.

Controls for matched candidate pool: original order, old gate, rank-only; patch budgets1/2/3. No changes to prompt/model/grader while isolating ordering. If live measurement is later needed, compare same task splits/seeds, report actual token/time costs. Prediction score is a heuristic scheduling signal, NOT a correctness score.

Optional severe-contradiction flag: >=3 decisive contradictions AND >=4 decisive observations AND contradiction ratio>=0.75, using only the named public-known probe set. Example1/4 matches is flagged. A single transfer-prediction miss out of6 is not severe. Flag initially changes neither eligibility nor count; hard elimination disabled. Enabling hard elimination requires the P0 audit and another measured ablation. It may still discard a good patch and must keep audit coverage. No destructive prune based on an unvalidated flag.
P2 · Nhóm theo hành vi · đặc tả đầy đủ
# 3. Exact behavioral signatures, bounded diversity request

Status: defined, signature/grouping helper implemented/tested; no model run. Group by ordered prediction vector across the SAME catalog/version/phase, independent of name or causal wording. Probe-ID ordering in JSON is irrelevant; missing/duplicate IDs are schema errors. fast/slow/uncertain retained explicitly. Two hypotheses are duplicate_on_catalog only if every prediction matches exactly. They are not proven to have the same causal mechanism or patch behavior.

Correct an earlier overbroad rule: compatible predictions with no observed contradiction are NOT necessarily exact duplicates. E.g. slow,uncertain vs slow,fast must not collapse. unknown observations do not redefine the authored prediction signature. Track distinct_hypothesis_ids, unique_prediction_vectors, decisive_diversity and unique_diff_hashes as DIFFERENT quantities.

Groups are a scheduling/reporting device, not an automatic skip. Rank group representatives first, then remaining group members if budget permits. P0 audit must still patch all archived members: equal behavior predictions can lead to different repairs. Keep member IDs, causes and outcome provenance. Record duplicate_signature separately from duplicate_diff.

If only1 unique vector remains, allow exactly1 NEW_HYPOTHESIS request: original issue/code, existing hypotheses/signatures, catalog, no hidden measurements, no patch. Require a different vector on >=1 probe; separately require >=1 decisive fast-vs-slow disagreement to count as useful diversity. Merely changing uncertain to a confident answer or renaming an ID is not evidence of an alternative mechanism. New hypothesis must explain a distinct proposed mechanism, but causal distinctness remains a review criterion rather than a formal guarantee. Never force a fabricated prediction just to meetK; unavailable/identical/unsupported output is logged, bounded call ends, proceed with original queue. This is addition, not rewriting original committed hypotheses.

Run as a separate factor from rank-only. Measure accepted new signatures, probe discrimination, patch success and marginal call/token cost. Do not call diversity improved just because IDs/count increased.
P3 · Model đề xuất probe · đặc tả đầy đủ
# 4. Model proposes an experiment separating two hypotheses

Status: defined; JSON schema specified, execution adapter not yet implemented. Use one fresh PROPOSE_PROBE call for a selected pair, not a rewrite-to-fit call. Inputs: original source, two frozen hypotheses, prior public observations and catalog. Output: bounded literal-string construction, predictions under H1/H2, explanation of why expected outcomes differ, no patch or Python/shell code. Must commit opposite decisive predictions (fast vs slow) BEFORE observing proposed-input runtime. Those are model-claimed implications, not validated facts about the hypotheses.

Safe executable interface is a host-owned DSL, not model-generated scripts: input = concatenate at most8 segments; each segment literal<=256 chars, repeat integer1..6000; total UTF-8 length<=131072 bytes; optional base_url<=2048 chars. Host invokes only the fixed target get_base_url with these string arguments in an offline Docker worker. No eval/exec, imports, paths, shell commands, writes or arbitrary callable selection from proposal. Malicious-looking strings remain target input data, never instructions. Reject oversized/malformed inputs and signatures already used as a public probe; save rejection, do not silently repair or run it. Max1 pairwise proposal at a time, max2 proposals/trajectory, no unbounded repair loop.

Observe function-only time,3 independent bounded subprocess samples; same predeclared fast/slow thresholds and grayzone as other diagnostic probes, plus actual return values/errors. Per-process3s, overall worker deadline/memory cap before execution. Original source only. If outcome matches one precommitted prediction and contradicts the other, mark consistency difference; do not claim causal proof or guarantee that the other cannot yield a good patch. No result or grayzone => inconclusive, not drop. If H1/H2 imply the same actual behavior under all available tests, say not distinguished.

Feed observations to rank-only queue by default. Hard pruning remains separate and off until audited; do not secretly recreate old binary gate. Differentiate proposed_new_input, opposite_expected_outcomes, actually_distinguishing_observation and improved_patch_result. Re-run a public reproducer only as a labeled control, not count it as novel discrimination. Predicted outputs, proposal, input hash, execution, rejection and model token costs saved independently.
P4 · Giới hạn revise · đặc tả đầy đủ
# 5. Revision is optional and bounded; unseen checks remain separate

Status: defined, not executed. Default0 hypothesis revisions. Optional ablation allows exactly1, with its own token/call budget. Do not repeatedly expose more measurements until model restates them. Match total generated-token allowance against a no-revision control where possible; report actual calls/input/output/time and any unused budget.

Commit initial hypotheses/predictions and evidence availability. If revision enabled, show only declared training/public evidence, keep source original and forbid edits in revision role. Archive new hypothesis version with parent IDs; never overwrite initial predictions. Freeze a fresh transfer probe catalog/outcomes as evaluator artifacts before revision, expose input definitions when asking predictions but keep outcomes hidden. Use >=1 fresh, meaningful decisive prediction to measure transfer; report initial accuracy, exposed-data accuracy and unseen-prediction accuracy separately. Once a probe outcome is revealed it cannot be reused as unseen in another revision.

Use predictions primarily to rank; unseen-probe miss alone does not block Patch. Patch acceptance remains behavior tests; final independent grader cannot trigger another revision or influence online selection. A review of candidate code must explicitly separate original hypothesis status from modified patch status, with unavailable output not blocking Python decisions.

One public issue and dependent hypotheses provide no generality estimate. After P0 audit, select additional development issues and a held-out task split, freeze inputs before tuning. Do not relabel previously observed tasks as unseen. Model output truncation/invalid schema is a stage failure, not a hypothesis-error count. If localize unavailable as in previous12B run, report no hypotheses; no invented rows or retry-until-success.
